## 七、发现的三处隐患

### 1. hosts 依赖 Steam++（要紧）

GitHub 全系域名在 hosts 里指向本机 127.0.0.1，靠 Steam++ 的加速器进程在 80 端口反代。**Steam++ 一退，github.com、raw.githubusercontent.com、hub.docker.com 立刻不可达**，Git 拉取、插件安装、脚本下载都会失败。且加速器改写的 hosts 可能干扰 Git 的证书校验（近 7 天 Schannel 15 条证书错误，或与此相关）。

- 若陛下常需 GitHub：保持 Steam++ 常驻并开机自启。
- 若不需要：退出 Steam++ 的「网络加速」后再清 hosts，恢复直连（需手动删 28 条）。

### 2. Python 指向项目虚拟环境（要紧）

用户级 PATH 首位是 D:\AI\hermes-agent\.venv314\Scripts，于是全局 python 命令实为 hermes-agent 的虚拟环境；而 pip 却指向 D:\AI\Python314。两处分家，日后装包容易「装到别处去了」。

- 建议：把 D:\AI\Python314 提到 venv 之前，或干脆不把项目 venv 放进全局 PATH。

### 3. 缺 ffmpeg

DSH 的轨迹录制（start_recording 的视频）需 ffmpeg，未装则只能用截图。若要录制功能，可 winget 装一个。
